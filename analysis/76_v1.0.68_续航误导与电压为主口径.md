# 76 v1.0.68：续航误导（94% / 6km）根因与"电压为主"口径

## 一、现场

11-26 14:29 截图：静置 74.8V、电量 **94%**、本次 17.8km、续航 **~6km**、均速 24、总里程 11752.0。
用户使用方式：**不彻底充满**，骑一段回家插电补一会儿再骑，所以"本箱"横跨两天。

数据：`raw_20261125_080147 / 120654 / 141608 / raw_20261126_102042 / 140246 / 165923.csv`。
复算：`tools/review_1125_26.py` → `analysis/r1126.txt`。

## 二、两个真 bug

### bug 1：续航被"满电续航 − 本箱已跑"压死

`HudState.rangeKm = min(电量 / 每公里耗电, estRange − kmCharge)`。
11-25 08:02 又一次误判满电（78.5V），此后两天没再充满，charge 锚点一直停在那里，
到 11-26 19:05 断电时 `kmCharge = 96.8km`。于是 capKm = 80 − 96.8 → **0**，
94% 的续航被压到 5～6km —— 就是截图那个数。

- 修：删掉这道 kmCharge 硬顶，续航只跟电量和满电续航走。`dist` 里那句话"避免多跑十几公里后推车"其实由空电锁 + 低电报警承担。

### bug 2：能量体检在"里程坐标失效"时把正确电压压成低值

能量体检用 `kmBox = odoKm − chargeOdoKm` 反推 soc。11-25 的 charge 锚点是误判满电，kmBox 累计到 96.8km（超过满电续航 80），
socEnergy 被算成 0，于是 `socRest > socEnergy + 15` 分支把 75.5V 查表 84% **压成 15%**（日志 `socV=15 socKm=84`）。

- 修：`kmBox > estRange × 1.05` 就跳过能量体检（坐标不成立，宁可不用这条校验）。

### bug 3（口径）：静置偏移 30 点以上时，账本不会落回电压

11-26 17:25 静置 68.99V（查表 23%），账本 60%，差 37 点 > 12 点死区 → reject；19:05 控制器断电、推车 3km。
用户原话："别管骑了多少公里，电压是能准确读到的"。

- 修（v1.0.68 的"电压为主"口径）：
  - 静置且查表值 **≥20%**（避开末端塌陷区）、且与上一次偏低读数相差 **≤5 点**（说明电压稳定停在同一处）→ **整段落回电压口径**，不再只挪 3 点。11-26 的两连停（23.1% / 26.9%）正好满足。
  - 向上同侧：查表 ≥20% 且差值 ≤20 点 → 整段对齐（补电后电量能真正抬回去）；差 >20 点仍按 10 点/次。
  - 末端（查表 <20%）保持原保守通道（三次确认 + 3 点/次 + 12 点预算），26.8km 读到 4% 那种塌陷反例仍挡在门外。
  - 判定"中途补过电"（查表比账本高 ≥8 点且 ≥20%）时，本箱里程坐标也重新起算（`setChargeAnchor`），"本箱已跑 96.8km"这种数不再出现。
