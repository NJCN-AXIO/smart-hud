# v1.0.18：换新电瓶后，旧电瓶学到的"耗电率"必须让位

你说得对：**新电瓶满电 80km，我按这个采信**。上一版那个"27km"的结论是拿**旧电瓶**的日志算的，
我不该把它当成这辆车的固有参数。抱歉。

但这条信息正好戳出一个真问题：**旧电瓶学到的东西，不会因为换了电瓶而消失。**

## 一、问题是什么

App 会把"每公里耗多少电（%/km）"存在手机里（`per_km_pct`），下次启动继续用。

- 旧电瓶：跑 26.8km 见底 → 学到 **3.7%/km**（折算满电 27km）
- 新电瓶：满电 80km → 真实 **1.25%/km**

换完电瓶如果不清账本，第一箱电就会**按旧电瓶的速度推算**：
明明还有 70% 的电，屏幕上已经掉到 40% —— 你会以为新电瓶也是坏的。这不是显示 bug，
是"用错的模型"。

## 二、两处修法

### 1. 满电时自动"回摆"（不用你操作）

每次真正充满（电压到满电静置值），把学到的耗电率**往默认值 1.25%/km 拉 35%**：

```
旧电瓶 3.7%/km → 充满一次 → 2.84 → 2.28 → 1.92 → … → 收敛到 1.25 左右
```

为什么是"回摆"而不是"清零"：清零后第一箱电完全没依据、只能全靠电压查表，
反而更容易跳。回摆既保留了"这辆车大概多重"的信息，又能在两三箱电内把旧电瓶的偏差洗掉。

同时理所应当的：如果电瓶其实真老化，后面每次停车静置校准会立刻把它学回去 —— **数据会自己纠偏**。

### 2. 设置里加一个"换了新电瓶"按钮（立刻生效）

`设置 → 电压账本` 那一段下面新增：

> **换了新电瓶（复位耗电率与电量锚点）**

点一下会：
- 耗电率（`per_km_pct`）清空 → 下次停车重新学
- 电量锚点（`soc_anchor_*`）清空 → 不再沿用旧电瓶算出的 4%
- 本箱电账本（`cycle_*` / `charge_*`）重置
- 并且**通知正在跑的前台服务立刻重建账本**（只改 SharedPreferences 是不够的，
  服务里那份 `SocTracker` 还抱着旧值 —— 这是容易漏的一环，用 `packResetRequested` 标记让 tick 自己重建）

## 三、你现在要做的两件事

1. **把设置里"满电续航"改回 80**（如果按我上一条改成了 30）。
2. **点一下"换了新电瓶"按钮**，然后正常骑一箱电。第一箱电结束、停车静置校准之后，
   学到的耗电率就会落到新电瓶的真实值附近。

## 四、以后怎么判断"电瓶真的不行了"

新加的那行日志就是干这个的：

```
range implied ~27km vs settings 80km  <- differs a lot, consider changing est_range
```

- 如果**连续几箱电**都是"实测 30km 左右、设置写 80" → 电瓶真的衰减了，把满电续航改小。
- 如果只有一两箱偏低、后面回升 → 是那次骑行重载/爬坡/低温，不是电瓶问题。
- 这批 11-17 的日志（78.3V 满电 → 26.8km 见底）属于**旧电瓶**，可以直接从判断依据里划掉。
