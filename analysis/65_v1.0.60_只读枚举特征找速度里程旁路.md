# 65 v1.0.60 只读探索：枚举 READ 特征，找直读速度/里程的旁路

## 背景

用户授权"尝试从控制器直读里程/速度，**只是读不要写入**"。在不向控制器写任何特征值
（红线：仅 CCCD `01 00` 开通知）的前提下，把所有带 READ 属性的特征读一遍，看控制器有没有
在 READ 快照里直接带速度、里程、电量。

## 特征属性（历史抓包 + 实车枚举）

| 特征 | 属性 | 旧版读取 | v1.0.60 |
|---|---|---|---|
| 0xFFF4 | READ | 连上读一次，75 次全空 | 纳入全量只读 |
| 0xFFF5 | READ / WRITE / NOTIFY | 未读 | 连上读一次 + 每 15s 重读 |
| 0xFFF6 | READ / NOTIFY | 通知通道（67B 广播） | 若带 READ 属性则读一次 |
| 0xFFF7 | READ / WRITE_NO_RESP | 计划读、未落地 | 连上读一次 + 每 15s 重读 |
| 0xAE01 | WRITE_NO_RESP | 不碰 | 不碰 |
| 0xAE02 | NOTIFY | 实验开关默认关 | 不碰 |
| 0x2A00 | READ（GAP 设备名） | 读 | 读 |

## 改动

- `NordicBleLink.readInfoOnce`：去掉"只读 GAP 名 + FFF4"白名单，**所有 READ 属性特征各读一次**，
  `READ <uuid> <hex>` / `READ-FAIL <uuid> status=` 落 GAT 日志。
- 新增 `diagReadPeriodic`：连接期间每 **15 秒**重读 FFF5、FFF7（只读），用来对比两次读值有没有
  随车速/里程变化；`closeManager` 复位计时。
- 兜底引擎 `BleLink`：`readQueue` 排队依次只读全部 READ 特征，读回调里继续拉下一条。
- 未新增任何 `writeCharacteristic`；红线自检通过（唯一写仍是 CCCD）。

## 下一份日志要看什么

1. `READ 0xFFF5` / `READ 0xFFF7` 行有没有带 hex 数据（不是空串、不是 READ-FAIL）。
2. 同一特征两次 15s 重读之间：
   - 字节随**车速**变 → 速度字段；
   - 出现**单调递增**的两/三/四字节组合 → 里程字段；
   - 电压/电量快照 → 可与 67B 广播交叉验证。
3. 若 READ 全空或恒定，说明控制器内部量（速度/里程）只在"写查询包后的 20B 回帧"里下发，
   只读链路拿不到——这条结论在 `analysis/06` 已有机制级证据，本轮用全量 READ 再复核一次。

## 仍未触碰的旁路

20B 遥测帧是"问出来的"：小程序每 4.5s 向 FFF5 写 67B 查询包才换回回帧。该路径需要写特征值，
本轮**不做**；若后续 READ 全部走空且用户明确放开"发与小程序同款、不改设置的查询帧"，再单独立项评估。
