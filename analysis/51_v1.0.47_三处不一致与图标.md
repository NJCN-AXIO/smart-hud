## 1. 本轮抓到的真 BUG：充满自动清零只清了里程，没清统计

### 现象推演

v1.0.45 加了"充满电自动把本次里程清零"。清零那一刻屏幕会变成：

```
本次里程   0.0 km
还能跑 ~80km · 均速 21     ← 均速是上一趟的
本箱电已跑 0.0 km
```

三行里有两行互相矛盾。原因很直接：

| 路径 | 清里程 | 折总里程 | 清 stats | 清 energy | 写 SUM |
|---|---|---|---|---|---|
| 长按清零 `resetTripInMemory` | ✅ | ✅ | ✅ | ✅ | ✅ |
| 充满自动清 `resetTripFoldingOdo`（v1.0.45） | ✅ | ✅ | ❌ | ❌ | ❌ |

`stats`（均速/最高速/运动时长）和 `energy`（本箱电 Wh）只有长按路径会清，
自动路径漏了 —— 于是"0.0km"旁边挂着上一趟的 21km/h 均速、最高速 38。

### 修法（不重复折叠，合并成一条路径）

`resetTripFoldingOdo(now, why)` 变成唯一的"清零"实现：

```java
float tripBefore = HudState.tripKm;
if (tripBefore > 0.05f) writeSum(now, why);     // 清零前先把这一趟写进 SUM，记录不丢
if (tripBefore > 0.05f) prefs.setOdoAccumKm(prefs.odoAccumKm() + tripBefore);  // 折进总里程
trip.reset(now);  HudState.tripKm = 0f;  HudState.gapWarn = "";
lastSummaryKmF = -1f;  lastAnnounceBucket = 0;   // 播报桶复位，否则新一趟不播
stats.reset();  energy.clear();
prefs.setStatsMax(NaN); prefs.setStatsMs(0); prefs.setLastTripSegKm(0);
HudState.maxKmh = NaN;  lastEstKm = -1f;         // 续航缓存作废
```

`resetTripInMemory`（长按）改成先调它，只额外做"手动电压哨点基准 / cycleSoc / 显示缓存"这几件它自己的事。
两条路径从此不会再分叉。

**注意**：`writeSum` 只在真跑过 > 0.05km 时才写。刚开机就满电（本次里程本来就是 0）不再往日志里刷 0 流量。

## 2. 顺手修掉的第二处不一致：`setCycleKm(tripKm)` 写了一个马上就要不存在的数

`maybeAnchorFull` 里原来是：

```java
prefs.setCycleSoc(100f);
prefs.setCycleKm(HudState.tripKm);     // ← 记下"此刻本次里程"
resetTripFoldingOdo(now, "full charge");  // ← 紧接着把这个数清成 0
```

净效果是"本箱电起点 = 一个已经不存在的里程"。现在满电起点直接写 0。
`kmThisCharge` 本身早就改用 `chargeAnchor`（按整车累计算），所以这个字段早就只剩存档意义，
但留着错值早晚会被人再读一次 —— 直接写对。

## 3. 第三处：导航那行会被"测速提醒"顶掉

`NavBridge.looksLikeNav()` 只要求"有单位 + 有数字"，于是高德的

- 「前方 500 米有测速」
- 「您本次行程超速 12 次」
- 「距离终点 3.2 公里」（这条其实该显示）

全部合格。旧逻辑靠"主文案 90 秒保护期"挡，可一旦 90 秒内没刷新主文案，
测速提醒就会挂到 HUD 底部，看着像导航在说胡话。

新增 `looksLikeTurn()`：非主文案必须含转向词（左转/右转/直行/掉头/路口/变道/靠左/靠右…）才允许上屏。
主文案口径不变（剩余/预计/到达/全程/总里程）。

## 4. 应用图标：原来借用的是系统图标

`AndroidManifest` 里一直是 `android:icon="@android:drawable/ic_menu_compass"`，
通知小图标也是 `ic_menu_compass`。桌面上看着像"某个系统设置"，通知栏里跟别的 App 撞脸。

本轮做了三件事：

- `drawable/ic_launcher_fg.xml`：108dp 仪表盘（深灰底弧 + 亮绿进度弧 + 白色指针 + 两根小刻度），内容全在 66dp 安全区，圆形/方形遮罩都不切；
- `drawable/ic_launcher_bg.xml`：和主界面同一个 `#0B0F13` 底色；
- `mipmap-anydpi-v26/ic_launcher.xml`：adaptive-icon（背景 + 前景 + monochrome，Android 13 主题图标可用）；
- `drawable/ic_stat_hud.xml`：24dp 纯白剪影（弧 + 指针），通知栏用。

清单改成 `android:icon="@mipmap/ic_launcher"` / `android:roundIcon=...`，
`BleService` 的 `setSmallIcon` 换成 `R.drawable.ic_stat_hud`。

> 踩坑记录：lint 建议"minSdk 26 就把 anydpi-v26 合并成 anydpi"——**照做会构建失败**
> （`resource mipmap/ic_launcher not found`），adaptive-icon 元素必须带 v26 限定符。这条警告保留，21 warnings 里的一条。

## 6. BLE 链路体检（本轮给出量化结论，未改代码）

用新增脚本 `tools/link_health.py` 把四份日志按 `SYS` 行统计（连接事件 / 有帧窗口 / `status=-5`）：

| 日志 | 时长 | 连接类事件 | 有帧窗口 | status=-5 | 备注 |
|---|---|---|---|---|---|
| raw_20261118_150145 | 5h | **215** | 11（最长 1433s、1149s） | **33** | 22 次"断开(10 0x0A 控制器没应答)" |
| raw_20261118_200840 | 2.5h | 72 | 8（503/871/622s） | 6 | |
| raw_20261118_224404 | 10min | 20 | 1（415s） | 2 | |
| raw_20261119_074216 | 3min | 30 | 2（116s、11s） | 4 | 开机那段 |

结论：

- 链路**每 10–15 分钟被控制器踢一次**是固件行为（`reason=0`/`10`），不是我们的 bug；
- 每次重连的无帧空窗 **11–14 秒**（电压显示 `--.-`、电量冻结），这就是"偶尔闪一下"的来源；
- 退避逻辑本身是收敛的（2→4→8→15s；133 走 4→8→16→24s；被抢走 8→20→45→60s），
  215 个事件集中在"用户反复开关小程序"的那一段，不是自己撞出来的风暴。

**本轮不动它**：迁移 `.retry(3,100)` 或调退避参数，都必须上车验证连接稳定性，
在没有实车的情况下改蓝牙 = 拿唯一的数据源冒险。要动就等一次"专用测试日志"（见第 7 节）。

## 7. 电量：看到了可疑点，但这轮**故意不改**

15:29 的原始帧（`raw_20261118_150145.csv`，逐秒）：

```
15:29:01 rv=70.35 v=70.35 vm=77.10 sag=5.03 thr=3.21 spd=30 soc=100 sra=23
15:29:16 rv=75.94 v=75.70 vm=76.84 sag=1.55 thr=0.76 spd=26 soc=100 sra=94
```

三件事一眼能看到：

1. `vm`（拿去查表的电压）稳定在 76.8–77.1，而 `rv`（真实端电压）在 70.3–75.9 之间摆 —— 中间那 3–5V 全是 `sag` 补上去的；
2. 30km/h、油门 3.21V 时补 5.03V，26km/h、油门 0.76V（基本松到底）时也补 1.55V。
   这个补偿在"巡航"这一档明显偏大（`rv + sag` 会算出 80.1V，比这辆车见过的最高电压 80.1 还贴着上限，
   物理上不可能）；
3. `sra`（不补压降直接查表）在同一秒是 23 / 94，和 `soc` 的 100 差 70 多点 ——
   "51 跳到 17"那种观感，本质就是"补压降"和"不补"两个口径在同一个屏幕上打架。

**为什么这轮不改**：手上没有任何"真实电量"的标尺（控制器不上报电流/剩余容量，仪表电量永远满格）。
现在动 `LoadComp` 的系数，等于又把用户最反感的"自己手搓"再来一遍 —— 可能把 15:29 那种"刚充满 3km、真的 96%"改成假的 60%。

下一轮要的是**一份能当标尺的日志**（见下），不是再猜一次。

## 8. 下一趟实测怎么跑（一次就够）

按用户"别让我记数据"的要求，全部靠自动日志：

1. 充满电，**拔掉充电器后静置 5 分钟**再开 App（这一步决定 `vx` 是 77.x 还是 80.x）；
2. 从头到尾只跑这一趟，**别开小程序**（单连接独占，开了就少一段数据）；
3. 跑到仪表掉第一格 / 明显没劲为止，中途不用记任何数字；
4. 结束时把这一份 `raw_YYYYMMDD_HHMMSS.csv` 发出来。

日志里已经带全了复盘要用的字段（`rv` 原始端电压、`v` 滤波后、`vm` 查表电压、`dc`、`sag`、`thr` 转把、
`spd`、`km`、`odo`、`soc`、`sra` 裸查表、`pk` 学到的 %/km），不用额外填表。
拿到这份，就能用"静置电压 ↔ 里程"这条曲线反推真实的 `sag` 系数与 `vEmpty`，而不是继续用 1.35/0.06 这组手调值。
