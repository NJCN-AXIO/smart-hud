## 1. 骑行中"电量自己往上爬两格"

**现象**：屏幕上电量隔一会儿 85 → 88 → 91 → 93 → 95，油门几乎没变。

**证据（`tools/soc_rise.py`）**：4 份日志里"`src=1` 且 `spd≥10` 时 soc 上升 ≥2 分"合计 23 次，其中
`raw_20261118_150145.csv` 独占 18 次，典型样本：

```
soc 85->88  rv=71.54 vm=75.81 sag=4.43 thr=2.79 spd=29
soc 91->93  rv=71.41 vm=75.94 sag=4.63 thr=2.89 spd=30
soc 93->95  rv=71.30 vm=76.02 sag=4.53 thr=2.81 spd=30
```

**物理事实（`tools/sag_probe.py`，30 秒窗）**：

```
rv 71.2..76.1 (Δ4.9)  sag 4.1..4.5  thr 2.55..2.81  spd 27..32
```

油门基本恒定、压降补偿值也稳定，**端电压本身在 30 秒内摆 4–5V**（控制器的瞬时采样噪声）。
所以不是算法错，是"输入在抖"，抖幅 ≈ 3–4 个电量点。

**改法（三层闸）**
| 层 | 之前 | 现在 |
|---|---|---|
| `SocSmooth` 中位窗 | 6 秒 | **12 秒**（`new SocSmooth(12000L, 96, 0.5)`） |
| `SocDisplay` 死区 | 2 分 | 骑行中 **3 分**（停车仍是 2 分） |
| `SocDisplay` 上升限速 | 2 分/秒 | 骑行中 **1 分/秒**（下降仍 2 分/秒） |

`SocDisplay.onEstimate(now, target, allowSnap, riding)` 四参重载；`riding = spd ≥ 8km/h 或 油门 > 1.5V`。
三参版本委托 `riding=false`，**原有 106 条用例语义完全不变**，新增 3 条骑行档用例。

**为什么不是"骑行时一律禁止上升"**：松油门后真实 OCV 会回升（用户此前也要求"下坡要还回来"），
禁止上升会让电量卡在坡底的读数上一整趟。压到 1 分/秒 + 3 分死区，够稳、也还能慢慢纠回来。

**验收**：骑行 10 分钟，电量只单向缓降；松油门滑行时最多补 1–2 分，不会连跳。

## 2. 清零「本次里程」后电量被反向顶高（真 BUG）

**根因**：`SocTracker.rebaseIfBehind()` 从 v1.0.10 就写好了，**但全工程一次都没调用过**。
本次里程清零后 `tripKm = 0`，而锚点还停在 26.9km，于是

```
predict(0) = 锚点电量 − 1.25%/km × (0 − 26.9) ≈ 锚点电量 + 34 点  → 直接顶到 100%
```

续航同时翻倍。用户看到的"清零后电量乱跳"、"清完又满电"就是这条。

**改法**：两处接线
- `resetTripFoldingOdo` 清零后 `socTracker.rebaseIfBehind(0f)`；
- tick 里每拍 `socTracker.rebaseIfBehind(HudState.tripKm)`（条件只在"比锚点还小 0.3km"时才动，平时零成本）。

## 3. 长按清零"折两次" → 总里程凭空多出一整趟（真 BUG）

**根因（竞态）**：界面先 `odoAccum += trip` 再广播；服务收到广播时若刚好有一拍 tick
把 `HudState.tripKm` 写回旧值（`trip.km()` 还没 reset），服务就**再折一次**。

**改法**
- 广播带 `EXTRA_ALREADY_FOLDED = true`（`BleService.EXTRA_ALREADY_FOLDED`）；
- 服务侧 `resetTripInMemory(alreadyFolded)`：`true` → 只清内存/落盘（`clearTripState`），**不折**；
  没带标记（老版本界面/其它入口）→ 照旧折。
- `resetTripFoldingOdo` 的 `tripBefore` 取 `max(HudState.tripKm, trip.km())`——界面先把 HudState 置 0 时，
  也不会漏折。
- 折叠/清零逻辑抽成 `clearTripState(now)`，两个入口共用，避免"清一半"。

**验收**：长按清零前后对比总里程，差值应正好等于"本次里程"（±0.1km）。

---

## 4. 清零弹窗开着还在骑车 → 那段里程被吞

**根因**：`onLongPressReset` 里的 `km`/`acc` 是**弹窗打开那一刻**的快照。

**改法**：点了"清零"之后**重新读实时值**再落盘（`kmNow = HudState.tripKm`、`accNow = prefs.odoAccumKm()`），
弹窗文案仍用快照（展示用），落盘用最新值。

---

## 5. 没骑车、拿着手机走路，里程也在涨

**根因**：`HudState.speedKmh` 恒为 NaN（67B 帧没有轮速），里程全靠 GPS 距离增量；
而 `TrackDistance` 只判"这些点像不像真移动"，走路 4–6km/h 照样通过。

**改法**：加一道**电动车物理下限**闸

```java
boolean looksLikeRiding = Float.isNaN(HudState.gpsKmh) || HudState.gpsKmh >= 8f;
```

- 稳定速度有数且 < 8km/h → 这段距离不记；
- 速度是 NaN 时照记（GPS 精度被判不合格 ≠ 没在骑，这是 v1.0.9 的老坑，不能回退）；
- `lastGpsKm` 无论如何跟着走，防止"走路那段攒着、一上车全补进去"；
- 30 秒节流记一条 `walk gate: spd=… skip …km` 到日志，方便你复盘确认它真的在拦。

## 6. 导航行会凭空消失；转向提示写"剩余"是错的

**根因 A**：高德导航时同时挂着多条通知（常驻"剩余 3.2 公里" + 转向"200 米右转"）。
`onNotificationRemoved` 只按**包名**判断 → 转向那条被撤掉，把常驻那条的剩余里程一起清了。

**改法 A**：新增 `lastKey` 记住"屏幕这行字是哪条通知来的"，撤掉的通知 key 不匹配就不清。

**根因 B**：转向提示的距离是"到路口"，写成"剩余 200m"会让人以为离目的地还有 200m。

**改法 B**：`compact()` 里非主文案（转向）用 **"前方 "**，主文案（剩余/预计/到达）才用"剩余 "。

## 7. "开几分钟闪退回桌面"——这次能抓到堆栈了

**问题**：崩溃钩子只装在 `MainActivity.onCreate`，所以
① 服务在后台自己崩 ② 开机自启起来就崩 —— 这两种**一条堆栈都留不下**，日志里全是 0 CRASH。

**改法**
- 新增 `HudApp extends Application`（manifest `android:name=".HudApp"`），**进程一启动**就装
  `Thread.setDefaultUncaughtExceptionHandler`，写 `CRASH thread=… 堆栈`；`HudApp.install()` 幂等，
  `MainActivity.installCrashLogger()` 改为委托它，不会叠两个 handler。
- `MainActivity` 的 `onResume/onPause/onDestroy` 各记一行 `ui resume / ui pause / ui destroy`：
  下次日志里出现 `pause` 但没有 `destroy`，说明是被别的 App 抢前台/被系统收起，不是崩；
  连 `resume` 都没有就进下一份日志，才是真崩。

**下次请直接发日志**，`CRASH` 行会带 Java 堆栈，不用再猜。

## 8. 弹窗/提示还是"原生安卓"味道

三处一起换皮：

| 位置 | 之前 | 现在 |
|---|---|---|
| 轻提示（24 处） | 系统灰药丸 `Toast` | `HudToast`：深色 `#141A21`、22dp 圆角、`#334150` 描边、淡入淡出，贴在三个按钮上方 92dp |
| 面板对话框 | `new Dialog(activity)` 继承浅色 Material 主题 | `Theme.Hud.Dialog`（`res/values/styles.xml`）：窗口透明、背景 `#0B0F13`、强调色 `#35E07A`、深色文字，输入框光标/选中手柄不再白底 |
| 面板弹出 | `dialog.show()` 直接弹 | 先判 `isFinishing()/isDestroyed()`，再 `try/catch` 兜 `BadTokenException`——这几个面板会从扫描回调/广播草弹，Activity 已销毁时再 show 会直接崩 |

> `HudToast` 用 `WeakReference` 持有当前提示条，避免 lint `StaticFieldLeak`（本轮 lint 仍是 21 条，没有新增）。

## 9. 顺带：开机自启失败的证据

`BootReceiver` 旧版先 `startForegroundService` 再 `RawLog.init`，一旦系统抛
`ForegroundServiceStartNotAllowedException`（红米自启白名单没放行 / Android 14 收紧），
异常只进 `Log.w`，日志文件一个字都没有。现在**先 init 日志**，失败也写
`boot -> service start FAILED: <异常类> <message>`。

## 实车验收建议（5 分钟能验完）

1. **关闭本次里程**：先看主屏总里程 T1、本次 K1 → 长按清零 → 总里程应变 T1（只差 ±0.1），电量不该从底下一路爬到 100%。
2. **电量稳定**：正常骑 10 分钟，电量只降不爬；松油门滑行最多补 1–2 分。
3. **走路不计里程**：断开蓝牙、拿着手机走 200 米，本次里程不应变化；日志里应出现 `walk gate: … skip …`。
4. **导航行**：高德导航中，转向提示出现/消失时，"剩余 X 公里"那行不该整行消失。
5. **闪退**：万一再闪退，日志里搜 `CRASH` 或 `ui destroy`，把那一份发我即可。
6. **弹窗皮肤**：设置/电压/标记三个面板、以及轻提示，都应是深色圆角、无系统灰药丸。
