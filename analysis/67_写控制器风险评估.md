# 67 向控制器写包的风险评估：值不值得（2026-11-24）

## 背景与约束

- 用户要求：0 成本、不拆车、不接线；只能从 App 和控制器端下手。
- 待评估动作：复刻小程序会话，向控制器 BLE 写 67B 查询包（FFF5），换回 20B 遥测回帧。
- 既定红线：只允许 CCCD `01 00` 开通知，不向任何特征写值。本轮只做风险与收益评估，不落地写代码。

## 已知写路径事实（来自 06 / 63 / 65 号笔记）

小程序完整会话里有三类写：

| # | 写目标 | 内容 | 性质 |
|---|---|---|---|
| 1 | FFF6 的 CCCD（handle 0x000B） | `01 00` | 订阅通知，红线内合法 |
| 2 | FFF5（handle 0x0008） | 67B `C9 9C 03 09 59 59 69 59 …`，约每 4.5s 一次 | 查询包（待评估项） |
| 3 | handle 0x0807（0x0800 区服务，我们连服务都没枚举到） | 9B `00 10 00 18 00 0A 00 58 02` | 配置/使能包，参数下发形态 |

控制器侧写特征清单：FFF5（READ/WRITE/NOTIFY）、FFF7（READ/WRITE_NO_RESP）、AE01（WRITE_NO_RESP）、0x0807（未枚举）。

## 风险分层

### R1 命令语义未逆向（基础风险）

- 67B 包 `[2..3]` 若按电压解是 115.35V，不合理 → 是报文类型/命令号，参数在其余字节。
- 手里只有一份静止低电量抓包；骑行中、各档位下查询包是否变化，没有样本。
- 包内可能含 CRC / 计数器 / 会话令牌，重发旧包可能被拒，也可能进异常态。

### R2 同一写口混载查询与参数下发（核心风险）

GATT 写回调在固件里通常按命令号分派：查遥测 / 改档位 / 改限速 / 改仪表协议 / 改刹车电平 / 恢复出厂 / 进升级流程。
FFF5 是复合 WRITE/NOTIFY 口；AE01 纯 WRITE_NO_RESP、0x0807 是配置口，形态上就是参数下发通道。
没有厂商协议文档，无法保证我们复刻的包一定落到"查询"分支。

### R3 持久化写入与变砖（最严重一档，软件侧无法排除）

电摩控制器参数（档位、限速、相序、刹车电平、学习状态、仪表协议、码数系数）多存 EEPROM/Flash：

- 临时态：档位/模式错乱，断电重启可恢复；
- 持久态：参数被改写，表现为不走、顿挫、异响、仪表不通信，需重新调参或刷固件；
- 变砖：命令空间若含 bootloader/升级入口，错包进入升级流程且校验不过，控制器不可启动。
App 侧的白名单写守卫只能限定"写到哪个特征、发什么字节"，拦不住固件按该字节改持久参数。

### R4 行驶中安全风险

误改档位、限速、刹车电平、P 档状态，在行驶中直接影响骑行安全；转把/速度未知时下发命令更危险。

### R5 保修与回滚

私有协议逆向写入，厂商售后不认；控制器异常时没有回滚到只读状态的通道，事故现场日志也不足以自证。

## 收益上限评估（写开之后能拿到什么）

| 数据 | 现状（只读） | 写查询后的预期 | 证据 |
|---|---|---|---|
| 电压 | 67B 广播 f[63][64] 已能读，66.0–76.1V 实测吻合 | 20B 回帧 `[2..3]×0.05` 也是电压，**无新增缺口** | 63 号结论一；06 号第 2 节五个锚点 |
| 车速 | 广播无；App 走 GPS + 盲区兜底 | 预期仍拿不到：官方小程序自己不显示速度，91 条 20B 回帧逐字节相同，无速度字段 | 63 号结论二 |
| 总里程 | 广播无单调递增字段；App 走对表基准 + GPS 增量 | 预期仍拿不到：里程是控制器本地算给仪表的，不上蓝牙；20B 回帧无里程字段 | 63 号结论一、二 |
| 电量% | 广播无 SOC；App 走静置电压查表 + 里程推算 | 预期仍拿不到：回帧无 SOC，官方小程序也只显电压不显百分比 | 63 号结论二 |
| 连接保活 | v1.0.60 只读保活（3s 读 2A00）正在验证看门狗假设 | 写包可能是心跳，但只读路径已有替代实验在跑 | README 4.10 |

**关键事实**：官方小程序（厂商自己的 App）界面只有电压、转把、P 档故障位 + 一排配置按钮，没有速度表、里程表、电量百分比。这说明控制器压根没把这三项放到蓝牙链路上；写查询最多把已有的电压换个帧型拿一遍，核心诉求三项预期全部落空。

## 结论：不值得现在做

1. **收益与诉求不匹配**：唯一坐实的回帧字段是电压，而电压只读广播已经拿到；速度/里程/电量% 在蓝牙链路上不存在，写开也拿不到。
2. **风险不可控且不可归零**：协议私有、字段未逆向、写口混载参数下发、持久化/变砖通道软件侧无法排除；R3/R4 直接关系到车和骑行安全。
3. **只读路径还没榨干**：v1.0.60 全量 READ 枚举的下一份实车日志尚未判读；只读保活假设正在验证；App GPS 速度/里程通道尚未上线。

## 若未来仍要试写，前置条件（仅记录，不是现在的动作）

1. 多抓小程序完整会话（静止 + 骑行 + 各档位），逐字节 diff，分出固定查询字与可变参数字。
2. PC 微信打开一次育宁小程序，解密 wxapkg 从源码确认命令分派与各写特征用途。
3. 停车通电、不起步、不转把；先拍照记录当前全部参数（72V/P档30秒/爱玛1/低电平刹车/5档/码数100%/M1）。
4. 只复刻 FFF5 上确认是查询的固定包；AE01、FFF7、0x0807 一律不碰。
5. 写守卫白名单到字节级；断电复位作为兜底；即便如此，持久化/变砖风险仍不能归零。

## 零成本、不拆车的可行方向（App / 只读侧）

- App 补手机 GPS 速度/里程显示，与控制器推算里程互校；
- 等 v1.0.60 实车日志判读 READ 旁路；
- 电量维持电压模型，继续攒本箱末段断电样本校准底部边界。
