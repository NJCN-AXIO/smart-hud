# v1.0.32：日志改成"能复算电量"的字段

## 为什么必须改

v1.0.30 把电量改成"电压直读 + 压降补偿"之后，`REC` 里还有一半字段是**旧锚点引擎**的产物
（`nud/rcv/aa/ak` 是纠偏与回升预算的计数，现在那些数已经不驱动显示），
而真正要用来调准的**关键输入却一个都没记**：

- 这一帧的原始电压是多少（现在只有滤波后的 `v`）
- 到底拿多少伏去查表（补偿后的 `vm`）
- 直接拿原始电压查表会得到多少（`sra`，用来量"补偿做了多少")

没有这三个数，我拿到日志只能看到"电量是多少"，看不到"为什么是这个"。

## 新 `REC` 字段表（每 2 秒一行）

| 字段 | 含义 | 用途 |
|---|---|---|
| `rv` | 这一帧的**原始**电压（未滤波） | 逐帧复算，核对是否和手机/小程序同源 |
| `v` | 3 秒 90 分位（大数字显示用） | 看显示是否平滑 |
| `vm` | **真正喂给电量表**的 OCV 值 | 核心：补偿后到底补到多少伏 |
| `dc` | 查表用的原始 `disp`（未补偿） | 和 `vm` 相减 = 本次补了多少 |
| `sag` | 本次压降补偿量 | 校验 1.35V/V 与 5V 封顶是否合适 |
| `thr` | 转把电压 | 压降的"电流代理" |
| `spd` | GPS 时速 | 速度项参考 |
| `km` / `odo` | 本次 / 总里程 | 对账用（和仪表比） |
| `soc` | 显示的电量 | 结果 |
| `sra` | 直接拿 `rv` 查表的结果 | 对照：补偿前会显示多少 |
| `rng` / `pk` / `er` | 剩余续航 / 每公里耗电 / 满电续航设定 | 续航合理性 |
| `vn` / `vx` | 本次会话最低 / 最高电压 | 判断是否满电、是否触底 |
| `wh` / `whc` | 最近 1km 平均功耗 / 本箱电已用 Wh | 能耗核算 |

删掉的：`nud`（纠偏累计）、`rcv`（回升累计）、`aa`（锚点电量）、`ak`（锚点里程）、
`gkm`/`acc`（GPS 原始量与精度，需要时看 `state` 行）、`mx`/`av`（极值，`SUM` 行里有）。

## 新增 `SOC` 行（每跳一格一条）

```
SOC 72 -> 71  vm=73.85 rv=71.02 sag=2.83 thr=2.71 spd=18 km=12.34
```

这是给调参用的：不用在时间轴上对齐，直接看这一串就能知道
"电压多少、补了多少、在什么负载下、跳了一格"。跑一趟回来，这一串就是最直接的证据。

## 采样频率与体积（没变）

- `FRM`：每帧 67B 全十六进制（约 345 帧 / 5 分钟，≈1MB/h）
- `REC`：每 2 秒（≈200B/行，≈360KB/h）
- `SOC`：每跳一格（几十条/趟）
- 单文件 16MB 自动轮转，保留 24 个；导出取近 24 小时 / 40MB

一天骑 10 小时大概 10–12MB，导出发我刚好。

## 你只需要做一件事

跑完（或隔几天）点「导出日志（直接发给我）」，把那一份 CSV 发我。
我不需要你记任何数——电压、转把、压降、电量、里程全在里面。
