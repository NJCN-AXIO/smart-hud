# v1.0.14：控制器"单连接独占"这个事实，改变了重连策略

你补充的这条信息非常关键：**控制器同一时刻只接受一条 BLE 连接** ——
App 连着时小程序连不上，小程序连着时 App 连不上，两个方向会互相把对方踢掉。

这条事实把之前所有的"断开/连不上"重新解释了一遍：

| 现象 | 以前以为是 | 实际是 |
|---|---|---|
| `reason=10`（0x0A 连接请求没应答） | 控制器旧链路没收干净 | **多半是有人占着**（小程序/另一台手机），它不接收新连接 |
| `err 133` | 偶发 GATT 错误 | **同一条链路上已经有 central 在通信** |
| "连上 30 秒就被踢" | 控制器看门狗 | 也可能是对方 App 把链路抢走了 |

## 改动 1：刚连上就被抢 → 先让一步，别去撞

```java
// 旧：只要断开就 1.5 秒猛回连
retryLater(reason == 0 ? 1500L : nextRetryDelay());
```

问题：如果链路是**被小程序抢走**的，我们 1.5 秒后回连，就等于把小程序撞掉；
小程序再抢回来，我们再撞 —— 两边一起进入"互相踢"的死循环，谁都用不了。

现在按"这次连了多久"分流：

- **连上不到 5 秒就被断** → 判定为"被抢占"，退 **8 秒**再试（日志写 `CONTENTION`）
- 连了 5 秒以上才断（控制器自己看门狗踢的典型情况）→ 仍然 1.5 秒快回连，不牺牲体验
- 压根没连上 → 正常退避 2→4→8→15 秒，`autoConnect` 用 90 秒超时兜底

## 改动 2：连不上的提示改成"说原因"

| 状态码 | 界面提示 |
|---|---|
| 133 | 控制器被占用(133)：小程序/另一台手机连着它，先退掉再连 |
| 10 / 8 / 62 | 连不上(0x0a)：控制器可能被小程序/另一台手机占着 |
| 其他 | 连接失败(status=N)，重连中 |

以前只有一句"连接失败，重连中"，骑手根本不知道要做什么。

## 改动 3：导航那一行不再被广告/push 骗

`looksLikeNav()` 以前只查关键词（"公里""分钟"），于是"高德地图已更新，离线包 8.2 公里"
这种推送也会被当作导航挂在屏幕上。现在要求 **单位 + 数字** 同时成立
（真实的导航文案一定是"剩余 3.2 公里 · 12 分钟"这种带数字的）。

## 实操建议（基于"单连接"这个约束）

- **骑车时别开小程序**。要看电量就关掉 App 再开小程序，或者干脆看 HUD（HUD 的电量口径现在比小程序更讲究）。
- 如果 HUD 底部一直在刷 `控制器被占用(133)` 或 `连不上(0x0a)`：先把微信里的小程序**彻底退出**
  （不是切后台，是从最近任务里划掉），再回来看 HUD —— 8 秒内会自动连上。
- 两台手机都装了 App 的话，同一时间只能有一台能连，另一台会一直重试（这是控制器的限制，改不了）。
