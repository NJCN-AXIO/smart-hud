# 08｜深度复盘：把"电量"从账面数改成物理数（v0.9.0）

> 上一版（0.8.0）刚打通实测电压。拿到真电压之后再回头看，会发现整套电量逻辑
> 还停留在"没有电压只能靠里程估算"的时代——电压一到手，旧口径反而成了新的误差源。

## 1. 复盘发现的六个真问题

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| 1 | 电量按**带载电压**查表 | 实测 73.9V 时表给 52%，但静置其实是 75.7V（约 70%） | 起步瞬间掉一档、松油门又涨回来，骑手不再信这个数 |
| 2 | 电量被**里程账本覆盖** | `src==SRC_BLE` 时代码仍会用 `cycleSoc - %/km × km` 覆盖电压查表结果 | 电压明明在掉，% 却按旧账走，且永远无法自纠 |
| 3 | 电压大字窗口 **10 秒** | 10s 均值在加速/爬坡时严重滞后 | "实时电压"名不副实 |
| 4 | 电压颜色**写死 67V** | 用户可改欠压值（默认 63），改成 65V 后颜色规则就失效 | 换电池/改参数后预警失真 |
| 5 | 剩余里程只用**电量法** | `soc / perKm`，perKm 是估出来的 | 估偏时"还能跑 xx km"跟着偏，容易半路推车 |
| 6 | 低电**只变颜色**，不提醒 | 骑车时不可能一直盯屏幕 | 该充电的时候没人告诉他 |

## 2. 改法与理由

### 2.1 压降补偿：`LoadComp`（新，`:core`）

铅酸放电端电压 = OCV − I·R。72V/500W 在 30km/h 时电流 7–10A、内阻约 0.2Ω，压降 1.5–2.5V。
用速度线性近似电流：

```
ocv = loadV + min(2.6, 0.06 × speedKmh)     // 停车 → 0 补偿，读到的是真静置电压
```

系数保守（宁可少补），封顶 2.6V。`LoadComp` 纯函数，5 条单测锁定：
停车不补、30km/h 补 1.8V、封顶、NaN 处理、补完查表确实更高但不会直接顶到 100%。

### 2.2 电量口径：电压为主，账本只兜底

- 有实测电压 → `soc(ocvSmooth)`，OCV 做 **30 秒慢平滑**（单调、不抖）
- 无实测电压 → 才回到"满电锚点 + %/km"的里程口径（`socFromKm=true`，界面照旧标注）

为什么把 v0.6.9 的"按里程数电"降级：电压是可测的真值，`%/km` 是估出来的，
一旦估偏（载重变化、冬天、换电池）就会一直偏且无法自纠；而静置电压本身就是电量的物理定义。

### 2.3 电压大字：窗口 10s → 4s

大数字要"实时"，4 秒均值既能压住 2Hz 采样噪声，又不会在加速时滞后。
电量则不用这个窗口——它走 30 秒的 OCV 平滑，两者分工明确。

### 2.4 颜色不再写死

`voltageColor` 改为按设置里的欠压值：`< vEmpty+3` 红、`< vEmpty+6` 黄、其余绿。
默认 63V 时即 66/69，与旧行为接近；改参数后自动跟着走。

### 2.5 剩余里程取"两条路里更保守的那条"

- 电压法 `(ocv − vEmpty) / 每公里压降`
- 电量法 `soc / 每公里耗电%`
- 两者都有就取 **min**

宁可少显示 3 公里，也不要让骑手信了虚高的数字然后推车。

### 2.6 低电震动提醒（新）

电量 ≤20% 或电压 `< vEmpty+3` → 震 1.4 秒（三段波形），**5 分钟最多一次**，
日志里留 `low power alert: soc=… v=…`。骑车时口袋里震一下，比屏幕变红有效。

## 3. 顺手修掉的隐患

- `checkMappingStillSame`（"帧变了电压不动 → 映射可疑"）只对**手工映射**生效：
  实测通道下怠速/P 档电压本来就会几秒不动，旧逻辑会在 3 秒内误报"映射可疑"
- 电压 8 秒过期时，把 OCV 平滑器一并 reset，避免恢复后前几秒电量用旧 OCV
