# v1.0.11：锚定之后，电压被彻底抛弃了

## 为什么"越挖越多"
不是新冒出来的 bug，而是早期版本只验证了"屏幕上有没有数字"，没验证"数字对不对"。
v1.0.0 定了一个口径：**停着量电压、跑着数里程**。这个口径本身没错（没有电流传感器时
最靠谱的一条路），但实现上留了一道缝：

```kotlin
val target = predict(km).let { if (it.isNaN()) socByVolt else it }
```

**只要存在锚点，`socByVolt`（电压查表算出来的电量）就被完全忽略。**
骑行时的显示值 = `锚点电量 − %/km × 里程`，纯粹按里程推。
而 `%/km` 是靠"两次静置锚点"学出来的 —— 骑手一天都在跑单，静置锚点可能一整天都拿不到，
**学偏的 %/km 没有任何东西能纠正它**。

这就是实测里"26.8km 显示 4%、电压却是 65V"的另一半原因：
- 上半截是 v1.0.8 修的：纠偏把自己挪的 4 点当真实消耗学进 `%/km`，把它顶到上限；
- 下半截是本版修的：即便 `%/km` 没错，**也没有任何机制把里程口径拉回电压口径**。

## 本版做法：SOC 融合（和商用 BMS 同一个思路，但更保守）

新增 `SocTracker.fuseWithVoltage(now, km, socByVolt)`，只在**骑行中**（里程 5 秒内还在涨）调用：

| 条件 | 值 | 为什么 |
|---|---|---|
| 分歧门槛 | > 12 点才认 | 带载压降补偿本身有 3–5 点残差，追噪声没意义 |
| 持续时间 | 连续 3 分钟才动 | 一次长坡/猛加速能临时压掉 6–8 点，不能立刻追 |
| 单次步长 | 3 点 | 和静置校准同一个 nudge 尺度 |
| 一箱电预算 | 12 点（复用 `nudgedTotal`） | 不允许被拖走，满电时归零 |
| 学习 | **不参与 `%/km`** | 学到的必须是真的骑行消耗，不能是我们自己的修正量 |

触发时写一条日志，事后可以精确对账：

```
soc fused toward voltage: pred=71 volt=48 -> 68 (used 3.0 of 12)
```

## 新增单测（3 条，:core 88 条全绿）
- `分歧不到 3 分钟不许动（长坡不能当成电量掉了）`
- `分歧持续 3 分钟后一次只挪 3 点且不改耗电率`
- `一箱电的纠偏预算用完就只守里程口径`

## 自查
- `:protocol` 11 + `:core` **88** 单测全绿
- `self_check.py` 6 项全过（vc48 / 1.0.11）
- 红线：唯一写仍是 CCCD `01 00`

## 实车怎么验
1. 跑 20km 以上，日志里**不应该**出现 `soc fused` 刷屏（分歧不到 12 点就不该触发）。
2. 如果出现，看那一行 `pred / volt` 的差 —— 相差 20 点以上说明真的是两个口径打架，
   这时电量应当**缓慢**朝电压靠，而不是瞬间跳（跳变就说明又有 bug）。
3. 停一次车看是否 `soc anchor learned`：学完 `%/km` 应该落在 1.2–2.2 之间。
