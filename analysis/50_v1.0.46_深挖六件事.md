# v1.0.46：这一轮深挖出来的 6 件事

## 1. 断链时 `lastVMap` 没清 → 重连头几秒还是用旧电压查表

v1.0.44 为了压掉 0↔2 抖动，让"候选样本不足时沿用上一次 vMap"。
但断链那段只 reset 了 `ocvCand`，`lastVMap` 还留着断开前那个数：

```
22:53  没电，最后 vMap = 64.59（≈2%）
07:42  充电后连上，第一帧 75.12V
       → ocvCand 只有 1 个样本 → 沿用 64.59 → 电量先按"没电"算了一遍
```

修法：断链时一并 `lastVMap = NaN`，重连第一帧就按新帧算。
（`lastLiveTickMs` 不能清 —— 它是"断了多久"的坐标，清了就永远开不了直跳确认窗。）

## 2. 早上满电出门，满电锚点会在骑行途中触发

`raw_20261119_074216.csv` 里：

```
07:42   full anchor @ 77.3V / 6.9km
```

当时人已经在骑了（后面几行 spd=25/27）。原因：判"停稳"用的是 `kmGrowingTs`
（最近一次里程增长时刻），冷启动那一秒它还是 0 → 被当成"停着没动"。
结果满电锚点在骑行途中触发，把当时 6.9km 的本次里程折进了累计。

修法两条：

- 判停稳的"里程没长"从 20 秒收紧到 **90 秒**，并且要求**服务已经跑够 90 秒**（冷启动不算停稳）；
- 另开一条"开机满电"路径：开机 60 秒内的第一帧若 ≥76.1V，就先处理一次（此时还没开始跑，
  折走里程不会误伤任何公里），之后不再重复。

## 3. 断开后电量是冻结值，低电提醒还在震

`raw_20261118_224404.csv` 里断开后 `soc=2` 一直被当成"实时电量"，
`maybeLowPowerAlert` 只看 `src != SRC_NONE`，于是断开 10 分钟里又震了一次。
手机揣在兜里走路被震，还以为是车出事。

修法：低电提醒只在 `src == SRC_BLE`（真的连着控制器）时触发。

## 4. 断档提示挂上就不撤

v1.0.43 的"离开 X 分钟未记录里程 · 长按总里程可对齐"没有过期时间，
只要不对齐就一直占着状态行。修法：挂 **15 分钟**自动撤（对齐/清零时立即撤）。

## 5. 0% 时写"还能跑 ~0km"，读起来像还有希望

## 6. 直跳没有日志，复盘时分不清"落位"和"被噪声带跑"

新增一行：`soc snap 2 -> 96 (vm=77.10, snap window)`。
只在真跳 ≥15 分时记，平时不刷屏。
