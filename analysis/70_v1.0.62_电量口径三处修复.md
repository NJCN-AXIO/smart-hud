# 70 v1.0.62：电量口径三处修复（据 69 号复盘）

## 背景

11-24 上午 21km 日志（69 号笔记）暴露：账本被续航硬顶压到 4%，静置 72.2V 锚到 42% 仍显示 4%，
低电提醒误报 5 次；本箱里程锚点未做满电校验。本轮三处修复，全部 App / 只读侧，不碰写控制器。

## 改动

### ① 硬顶分支只压续航，不再压 SOC（BleService 续航护栏）

- 旧：`capKm ≤ 1` 时把 `socVal = 4`、`rangeKm = 0`，之后每轮刷新都被压回 4。
- 新：`rangeKm` 仍按 `estRange − kmCharge` 保守封顶；SOC 交还给里程账本 / 静置锚点，硬顶不再覆盖。
- 依据：11-24 静置 72.2V→42%、70.6V→28% 被上屏前覆盖成 4%，显示与电压口径打架是最差的信任损失；
  续航保守封顶保留，不会多报里程。

### ② 低电提醒加静置开路电压闸门（maybeLowPowerAlert）

- 新增入参 `ocv`（HudState.ocvV）与 `atRest`（HudState.socAtRest）。
- 静置且 OCV ≥ 70V → 跳过提醒，留日志 `low power skip: rest ocv=…V >=70, soc=…`。
- 闸门只在静置口径生效；骑行中带载压降仍走原 `vLowLine`（vEmpty −4 +3）判断，深亏电不误放。
- 依据：误报 5 次里 70.2 / 72.0 / 70.1V 都是静置高电压；真到底的带载 58.7V 场景速度 ≥12，不进静置分支。

### ③ 本箱里程锚点满电校验（kmCharge）

- 旧：只要 `chargeSoc / chargeOdo` 非 NaN 就参与 `kmCharge = odo − chargeOdo`。
- 新：再加 `cSoc ≥ 95f` 闸门；半路残留的旧锚点不参与续航硬顶，避免把上一箱里程算进这一箱。
- 锚点建立路径（applyFullAnchor：`setChargeAnchor(100f, odoKm)`）核对无缺陷，本轮只补校验。

## 未改动

- emptyLatch 空电锁逻辑不变（真断电保护才立，真充满才解）。
- estRange 每箱实际里程自动改写保留。
- 红线：仍无任何 `writeCharacteristic`，唯一写是 CCCD `01 00`。

## 验证

- 红线自检通过；:protocol 11 条、:core 112 条单测全过；assembleDebug 通过；APK 版本 99 / 1.0.62 一致。
- 蓝牙真连、静置锚点与误报消除需下一箱实车日志复核。
