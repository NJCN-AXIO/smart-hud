# v1.0.10：两个"看起来没事、其实一直在误报"的缺陷

这一轮不再加功能，专挑"能骗过眼睛"的地方。

## 1. 🔴 「映射可能不对」的警告会天天误报，而且撤不掉

`checkMappingStillSame()` 的判定是：**帧在变、解出的电压一位不动，连续 5 帧** → 点亮
`HudState.mapSuspect`，屏幕底部出现一行黄色提示。

这个判定有两个致命问题：

1. **等红灯就会触发**。电压字段是 0.01V 一档，静置时几十分钟都不翻一位；
   而帧里其它字节（转把、故障、尾字节）一直在变 → "帧变了、电压没变" 完全成立。
   2Hz 下 5 帧 = **2.5 秒**。也就是说：**停一次红灯就点亮一次**，每天都在误报。
2. **置位之后没有任何地方能撤**。`HudState.mapSuspect = false` 只出现在
   `rebuildDecoder()` 里（改设置或重启服务才会走到）。所以一条假警告会一直挂在屏幕底部，
   骑手看到的是"映射可能不对"，会以为解析坏了 —— 实际电压一直是准的。

**修法**
- 只在**真的在骑**的时候判定（里程 5 秒内还在长，或 GPS 速度 > 5km/h）。骑行中电压一定随负载动，
  这时电压纹丝不动才是真的可疑。
- 门槛从 5 帧（2.5 秒）提到 **10 帧（5 秒）**。
- 电压一旦动了（任何一位变化）就**立即清除**怀疑，并写一条 `map suspect cleared` 日志，事后能对账。

## 2. 🟠 「满电续航」改了不生效，要重启服务

`socTracker.defaultRangeKm` 只在 `rebuildDecoder()` 里从 `prefs.estRangeKm()` 同步一次。
tick 里比对的 `cfg` 签名字符串（偏移/长度/大小端/比例/偏置/满电/欠压）**没有把满电续航放进去**，
所以：在设置页把"满电续航"从 80 改成 45，签名不变 → 不重建 → `defaultRangeKm` 还是 80 →
**没有学习值时的 `%/km` 初值仍按 80km 的乐观口径算**，电量掉得比实际慢。

**修法**：把 `estRangeKm` 加进 `cfg` 签名。改完下一秒自动重建，不用重启。

## 3. 🟡 `VoltFilter.median()` 是假中位数（顺手修）

`median(nowMs)` 原来直接 `= value(nowMs)`，而 `value()` 是 **0.9 分位**。
`calibrateSocAtRest()` 里那道"静置窗是否稳定"的闸门比的是 `value()` 与 `median()` 的差 ——
同一个数相减恒为 0 → **闸门从 v1.0.4 起从未生效**，"刚松油门/刚起步"的窗口也会被当成静置平台拿去当电量锚点。

**修法**：抽出 `quantileOf(nowMs, q)`；`value()` = 0.9 分位，`median()` = 真 0.5 分位。
新增单测：输入 `58/60/62/64/70`，必须得到 `value=64`、`median=62`，且两者差 > 1.0V。
（闸门现在真的会拦人了 —— 拦对了才是对的，拦错了会退回每 90 秒/3 分钟/8 分钟的重试，不影响可用性。）

## 4. 🟡 里程折算多了一道多余条件（上一版遗留的清理）

只要 `gpsKm` 涨了 ≥1m 就记，不再要求"显示速度 ≥3km/h"。`gpsKm` 本身就是四道闸过滤后的产物。
