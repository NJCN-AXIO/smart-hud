# v1.0.43：里程怎么会差 22 公里，以及顶部状态为什么要改

## 一、差的那 22 km 不是算错，是"App 没在跑"

日志（`raw_20261118_150145.csv`，15:01:45 → 19:53:06，**近 5 小时、10,666 行，零 CRASH**）里：

```
REC 19:53:06 ... km=4.88 odo=11248.9
```

也就是说 App 自己认为：总里程 11248.9 = 基准 11244 + 本次 4.88。
而仪表是 11271 —— 差的 22.1 km，是**App 没在采集的时候车跑掉的**。
GPS 只在 App 运行时每秒采一个点；App 不在，那段路对 App 就是不存在，
这不是算法能补回来的（仪表自己靠轮速计，它当然一直在记）。

所以这一版分两步：

### 1. 先别让它随便停（治因）
- 新增 `onTaskRemoved`：你从最近任务里划掉 App，服务会在 **2 秒后**用闹钟自己爬起来
  （`setAndAllowWhileIdle`，Android 12+ 不需要精确闹钟权限），并把 `trip.flush()` 落盘。
- 服务本就是 `START_STICKY`，系统回收后会重建；本次里程每 5 秒落盘一次（原有逻辑），
  所以"被杀"最多丢 5 秒。

### 2. 真断了就明说（治果）
- 服务每 30 秒写一个 `last_run_ms`。
- 启动时若发现距上次运行 **超过 10 分钟**，状态行挂一句：
  `离开 37 分钟未记录里程 · 长按总里程可对齐`
- 长按「总里程」输入仪表读数 → 立刻归位，这行提示自动消失（写进日志 `ODO_ALIGN`）。

这样你不用"一直开着不敢切 App"：切后台不受影响；真被系统清理了，界面也会告诉你差在哪、怎么一分钟对齐。

## 二、顶部连接状态：固定位置 + 四个词

之前是 `Row(SpaceBetween)` + 文本 `weight(fill=false)`：文字一变长，整行的剩余空间重新分配，
于是状态词一会儿贴左、一会儿被挤到中间甚至压到时速。截图里那句
`断开(10(0x0A) 控制器没应答连接请求)，自动回连` 就横跨了半屏。

现在：
- 结构固定 = 圆点 + 6dp + **固定 96dp 宽**的文案槽（单行、超长省略）+ 弹簧 + 时速
- 文案只有四档：**已连接 / 连接中 / 等待连接 / 未连接**
- 详细原因（"控制器没应答连接请求"这种）挪到底部状态行，那里本来就有位置，
  而且是"能据此做动作"的一句话

顺带修了两处残句：
- `还没连上控制器 · 电压是按  的读数推算`（中间空一块，因为 anchorAge 拿不到时间）→
  改为 `控制器未连接 · 电压为推算值`
- 状态行现在按顺序排：定位提醒 → 断档提醒 → 语音未就绪 → 手机低电

## 五、下次请这样验

1. 连上跑一段，**中途从最近任务划掉 App**，再骑 2–3 公里。
2. 重新打开：总里程应该没断（最多差 5 秒那段）；若断了，状态行会出现"离开 X 分钟未记录里程"。
3. 看顶部左侧：`已连接` 四个字应该钉在固定位置，不会随文字长短移动。
4. 断开控制器：应显示 `未连接`，底部状态行给原因，而不是半屏长句。
