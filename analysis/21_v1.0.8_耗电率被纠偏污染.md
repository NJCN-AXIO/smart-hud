# v1.0.8：再深挖出 3 个 BUG（都和"电量越算越低、续航越来越短"有关）

这轮继续只审代码、不加功能。三条连起来正好解释了你在实车看到的
「26.8km 只剩 4%，还能跑 ~1km」。

---

## 1. 🔴 根因：**纠偏自己被当成"耗电"学进去了**

`SocTracker.anchorRestGuarded()` 在"电压比里程推算低得不多"时会把锚点往下挪几点
（防电池老化/表偏低）。问题是挪完它紧接着调 `anchorRest(pred - step)`，
而 `anchorRest` 会**从这次锚点变化里学习"每公里耗电 %"**：

```
dSoc = 旧锚点 - 新锚点    ← 这里面包含我们刚刚人为挪下去的 4 点
dKm  = 这段里程
perKmPct ← 越学越大
```

一个红绿灯停一次就挪 4 点，学一次；一天停十几次 → `perKmPct` 被顶到上限 **3.0**。
3.0 %/km 意味着满电只能跑 33km，于是**电量掉得飞快、续航算得极短**。
你看到"4% 还能跑 1km"就是这个数被学到上限的结果（4 ÷ 3.0 ≈ 1.3km）。

**修法**
- `anchorRest(..., allowLearn = false)`：纠偏这一步**不参与学习**；
- 学习只学"真实的消耗"，不学"我们自己的修正量"；
- 上限从 3.0 收到 **2.6**（72V/21Ah 实测满电 45–80km ↔ 1.25–2.2%/km，2.6 已经是电池很旧的值）；
- 新增单测 `向下纠偏不会把耗电率学坏`（连停 8 次，perKmPct 必须还停在 1.25）。

## 2. 🟠 「本箱电已跑 X km」和「本箱电已用 Wh」自相矛盾

上一版把 Wh 改成跨清零累计（正确），但**已跑里程仍然用 `cycleKm`（本次里程坐标）**，
长按清零时 `cycleKm` 被设成 0 → 里程归零、Wh 却接着累计。同一个弹窗里两个数互相打脸。

**修法**：坐标换成**整车累计 `odoKm`**（清零时会 `accum += 本次`，所以它是连续的）。
现在本箱电的"跑了多少 km"和"花了多少 Wh"是同一本账，清零只清"本次"。

## 3. 🟠 「校准满电续航」的公式错的

旧逻辑：`estRange = 本箱电已跑 + 3`。
它假设"你说快没电 = 电量 0%"，可电量本身有误差、你往往还剩 5% 就点了；
而且 `estRange` 又反过来决定 `%/km` 的初值 —— **一次误点就能把整套口径带偏**。

**修法**：按物理定义反推
```
满电续航 = 已跑里程 ÷ 已用电量% × 100
```
- 只有"至少用掉 20%"才用这个公式（5% 的样本里 1–2 点误差就能算出 40 或 150km）；
- 不够 20% 时退回"里程 + 3km"的粗略口径，并说明原因；
- 日志记下 `used%`，以后能复盘这次校准靠不靠谱。
