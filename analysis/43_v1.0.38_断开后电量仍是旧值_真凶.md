# v1.0.38：断开后电量仍是"很早之前"—— 真凶找到

## 结论先说

不是"冻结值取错了"，是**你以前手输过的一个电压锚点一直在替它算**。

## 证据链

你这批日志里有一行（14:03 的 `state`）：
```
state v=71.3 src=3 soc=38 km=0.07
```
- `v=71.3`：正好是 71.3V —— 这是早期版本里"手动电压"功能被手输进去的值，不是实测帧。
- `src=3`：`SRC_MANUAL`，手动锚点。
- `soc=38`：这个锚点查表出来的电量。

而同一趟里，控制器直读的帧是 `rv=71.84 v=74.22 src=1 soc=100`。

断开那一刻，`liveV` 被清成 `NaN`，`disp` 空了出来 —— 于是"手动电压顶班"那块接管：
用几天前的 71.3V 按里程往下推 → 得到 70.6V → 查表 → 38% / 29%。
你截图里 14:16 那屏"70.6V · 29%"，就是这么来的。它当然"很早之前"，因为源头就是很早之前的。

v1.0.37 加 `lastLiveSoc` 只解决了"冻结谁"，但这两块覆盖代码还是能把它改回去 ——
断线时代码顺序是：先算 `socVal = lastLiveSoc`，**然后**手动电压块把 `disp` 补上，
**再**用 `disp + sag` 重算 `socByVolt` 并覆盖 `socVal`。后写的赢。

## 三处修改

1. **手动锚点退役**（根因）
   `onNotify` 收到第一帧带电压的数据时，若这个手动锚点已存了 6 小时以上，就从内存和
   SharedPreferences 里一起清掉，并落一行日志：
   `manual anchor retired (71.3V) : live voltage now available`
   （6 小时内不清，避免你刚手动标过一次、值当场消失。）

2. **两处覆盖加闸**
   - 手动电压顶班：`if (Float.isNaN(disp) && !Float.isNaN(HudState.manualV) && Float.isNaN(lastLiveSoc))`
   - 离线重算：`if (!live && !Float.isNaN(disp) && Float.isNaN(lastLiveSoc))`
   只要这次会话真读到过电量，任何旧锚点都不许再改显示值。

3. **冻结值落盘**（防闪退后退回旧值）
   新增 `last_soc_shown` + `last_soc_ts`。同步电量时一并写入；服务启动时读回（12 小时内的才认）。
   这样即使进程被杀，断开后也不会退回账本里几小时前的数。

另外加了诊断行：断链那一刻落
```
link lost: freeze soc=NN (last live)
```
以后你发日志，我直接能看到"断开瞬间冻结的是几"，一眼判断是否还对。

## 现在的行为

| 场景 | 电压 | 电量 |
|---|---|---|
| 连着控制器 | 实时帧（3 秒窗中位数） | 直读查表 + 6 秒平滑，每 60 秒同步一次账本 |
| 刚断开 | `--.-`（不再拿旧锚点假装有电压） | 冻结断开那一刻的值，副标题"显示断开前读数" |
| 杀掉进程再打开 | `--.-` | 从盘里读回 12 小时内的冻结值 |
| 从没连上过（全新装） | `--.-` | `--%` |

## 上车请验这一条

1. 连着看几秒（记下电量，比如 92%）→ 关掉控制器电源（或退出小程序抢连接）。
2. 断开后那屏电量应当**就是 92%**，电压 `--.-`。
3. 隔 1 分钟再看，数字不动。
4. 日志里应有 `link lost: freeze soc=92`；如果之前存过手动锚点，还会有一行 `manual anchor retired`。
