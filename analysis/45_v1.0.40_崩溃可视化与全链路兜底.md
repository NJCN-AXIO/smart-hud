# v1.0.40：闪退从此"自己会说"

## 先说已知的那次崩溃

你上一批日志（`raw_20261118_140903.csv` 等）里出现的 3 次闪退，堆栈是同一个：

```
1794982323535,SYS,CRASH thread=main java.lang.IllegalArgumentException: Padding must be non-negative
  at androidx.compose.foundation.layout.PaddingElement.<init>(Padding.kt:336)
  at com.hud.delivery.ui.HudScreenKt.HudScreen(HudScreen.kt:226)
```

那是 v1.0.36 的防烧屏位移写成了 `.padding(-3.dp)`，**v1.0.37 已改成 `.offset()` 修掉**。
如果你装的是 1.0.37 之前那版，看到的还是这个老问题；如果装的是 1.0.37/1.0.38/1.0.39 还崩，
那就是**另一个异常**，只是目前没有任何日志能证明是哪个 —— 所以这一版的核心不是"再猜一个修一个"，
而是**让崩溃自己开口**。

## 这版做了三件事

### 1. 崩溃直接显示在界面上（最重要）
以前崩溃只写进 `raw_*.csv`，你得连电脑、翻文件管理器才能拿到。现在：
下次启动时若发现 24 小时内有 `CRASH` 记录，**开屏就弹一张卡片**：

> 上次运行崩了一次
> （日志文件名 + 完整堆栈前 420 字）
> [复制这段文字] [知道了]

点「复制」进剪贴板，直接粘到微信发我就行 —— 不用装 adb，也不用找文件。

### 2. 主线程/回调线程全部兜底，崩了也不带走进程
三个高频入口原来是"裸奔"，任何一处没预料到的异常都直接杀掉进程（表现出来就是
"打开后固定几分钟闪退"）：

| 入口 | 线程 | 现在 |
|---|---|---|
| `tick`（1 秒一次的主循环） | 主线程 | `try/catch(Throwable)`，异常写 `SYS tick-ex`，下一秒继续跑 |
| `onNotify`（每帧回调） | BLE 回调线程 | 已拆成 `handleFrame` + 外层兜底，异常写 `SYS frame-ex` |
| `onLocationChanged`（每秒定位） | 系统回调线程 | 已拆成 `handleFix` + 外层兜底，异常写 `SYS fix-ex` |

兜底不等于掩盖：堆栈照样进 CSV，只是**不再黑屏**。同类异常只记前 3 次，之后 60 秒一条，
日志不会被刷爆。

### 3. 日志第一行写版本号
```
build v1.0.40
```
以后你发任何一份日志，我第一眼就能确认"这是哪个版本产生的"，
不会再出现"你装的是不是新版"这种来回猜。

## 请你这样验一次

1. 装 1.0.40，**先别连车**，让它在桌面放着跑 30 分钟以上（时间够长才覆盖到"几分钟后闪退"那个窗口）。
2. 如果它崩了：再打开 App，第一屏应该弹"上次运行崩了一次"——**截图发我**即可。
3. 如果它没崩：说明之前的闪退确实是 1.0.36 的 padding 问题，已修好。
3. 顺便把这次新产生的 `raw_*.csv` 发我一份，我核对 `build v1.0.40` 这行在不在、有没有 `tick-ex` / `frame-ex` / `fix-ex`。
