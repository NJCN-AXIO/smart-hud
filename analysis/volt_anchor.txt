# 电压锚点 ↔ 候选编码（bytes[2..3] 小端 × 0.05V/LSB）
# 全部来自育宁科技小程序 M1 页的「电池电压」读数，不是估算。
#
# 时间        读数     换算(×20)   小端字节   场景
# 11-16 20:06 69.7V -> 1394 = 0x0572 -> 72 05   静置，P档（有抓包，但帧里是 0x0594）
# 11-16 20:42 71.4V -> 1428 = 0x0594 -> 94 05   ★ 唯一"读数+同场帧"都对得上的点
# 11-16 21:06 72.3V -> 1446 = 0x05A6 -> A6 05   静置，P档
# 11-17 07:46 78.3V -> 1566 = 0x061E -> 1E 06   充满后静置，刹车故障、转把 0.8V
# 11-17 07:47 74.9V -> 1498 = 0x05DA -> DA 05   骑行中，转把 2.6V（1 分钟掉 3.4V = 压降）

69.7 -> 1394 = 0x0572
71.4 -> 1428 = 0x0594   <-- 抓包帧里就是 94 05（唯一同刻验证过的一次）
72.3 -> 1446 = 0x05A6
74.9 -> 1498 = 0x05DA
78.3 -> 1566 = 0x061E

# 五个读数全部落在 0.05V 的整数格上（0.7/0.4/0.3/0.9/0.3 除以 0.05 都是整数），
# 与 0.05V/LSB 自洽；但也说明 0.1V/LSB 同样能解释 —— 只有帧能区分（帧里是 1428，不是 714）。

# 下一步只需一眼：
#   充满电（78.3V 左右）时看 App 里那 20 字节帧的开头，
#   若是 C9 9C 1E 06 ... -> 候选成立，可以钉死；
#   若开头还是 C9 9C 94 05 ... 而别的字节在变 -> 这个位置不是电压，换候选。
#
# 附：07:46 -> 07:47 从 78.3 掉到 74.9（转把 0.8 -> 2.6），
# 3.4V 是骑行压降（铅酸内阻 + 大电流），不是电量掉了 3.4V。
# 所以开机第一分钟看到的百分比会偏低，静置会回一些 —— 这方向对防推车有利（偏保守）。
