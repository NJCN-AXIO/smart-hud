# v1.0.15：控制器是"被动设备" —— 退避必须比 8 秒更耐心

你补充的第二条：**控制器不会主动去连谁**，只有你打开小程序时，它才会被小程序连走。

这条把 v1.0.14 的"退回 8 秒"直接否掉了，原因很直接：

> 你打开小程序 → 链路被它拿走 → 我们 8 秒后就回连 → **正好把小程序踢掉** →
> 你刚打开的小程序界面一直转"寻找设备/连接中"。

也就是说，v1.0.14 的 8 秒退避只是把"互相踢"的周期从 1.5 秒拉长到 8 秒，仍然是互相踢。
而你打开小程序通常要看十几秒到一分钟（看电压、看故障码、看里程），8 秒必然撞上。

## 现在：阶梯退避，最长 60 秒一次

```
第一次被抢 → 8 秒后重试
还是被抢（又断在 5 秒内）→ 20 秒
再来 → 45 秒
再来 → 60 秒（封顶）
```

- 连上成功 → 立刻归零回 8 秒（下一次被抢还是先给一次快速机会）
- 你**手动点顶部重连** → 也归零（那是你明确想立刻抢回来）
- 界面会显示：`控制器被小程序占着 · N 秒后再试`

代价是：你关掉小程序后，HUD 最多等 **1 分钟**才自己接回来（如果等不及，点一下顶部就是立刻连）。

## 为什么这个折中是对的

按"谁最需要这条链路"判断：

| 场景 | 谁在用 | 应该优先谁 |
|---|---|---|
| 骑车送单 | HUD（你不可能一边骑一边看小程序） | HUD |
| 停下来查故障码/看电量 | 小程序（主动打开的那一刻） | 小程序 |

所以：**你主动打开小程序时，HUD 让路**；你关掉后 HUD 自动接管。
这样两个工具不会互相打断，而不是像以前那样谁先抢到谁赢、两边都闪。

## 附：这也解释了 221542 那份日志

```
DISCONNECTED reason=10 afterMs=30077   ← 链路活了 30 秒后被拿走
DISCONNECTED reason=10 afterMs=0       ← 之后 5 次全连不上（小程序正占着）
```

`afterMs=0` 连不上 = 控制器被小程序占着、不接收新连接（0x0A）。
以前每隔 8–19 秒撞一次，现在会退到 8 → 20 → 45 → 60 秒，不再互相打断。

## 车上怎么验
1. **打开小程序看电量**：HUD 应当显示"控制器被小程序占着 · N 秒后再试"，并且**不再把小程序的连接踢掉**（小程序能稳定显示数据）。
2. **关掉小程序**：HUD 在 8 秒到 1 分钟内自己接回来（连续被抢过几次的话要等久一点）。
3. 等不及就**点一下屏幕顶部**（`frames==0` 时单击=立刻重连），会马上抢回来。
