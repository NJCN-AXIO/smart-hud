# v1.0.22：不用你记任何东西，日志自己把要的都记上

## 你说的问题

> "不要让我记录电压、行驶里程、掉电量等等，太麻烦了。需要什么数据都能记录到日志里面，
> 到时候我直接发日志给你，最多截几张图。"

原来的日志确实不全：只有原始帧 + 每 30 秒一条 `state` 行，缺"当时界面上显示的是多少"、
缺"压降补偿了多少"、缺"锚点在哪、学到的 %/km 是多少"，所以每次都得你手记才能对账。

## 现在的做法（全自动，你什么都不用做）

| 新增 | 频率 | 记了什么 |
|---|---|---|
| `REC` 行 | **每 2 秒** | 端电压 / 上屏电压 / 静置电压 / 压降估计 / 转把 / GPS 时速 / GPS 累计里程 / 定位精度 / 本次里程 / 整车累计 / 显示电量 / 电压口径电量 / 锚点电量+里程 / 学到的 %/km / 设置里的满电续航 / 纠偏已用 / 回升已用 / 剩余续航 / 每公里电耗 / 本箱电已用 Wh / 最高速 / 平均速 |
| `SUM` 行 | **每趟自动**（清零时 / 停下 60 秒 / 退服务） | 这趟的起点→终点电量、起点→终点电压、电压最低最高、最高/平均速、纠偏与回升动过多少、学到的 %/km、耗时 |
| `SYS` 行 | 事件发生时 | 原有：断连原因、摄像头/占用退避、GPS 断流、静置校准每一步的判决、纠偏动没动、回升加减、满电锚点、换电瓶复位 |

也就是说：**你只要跑一趟 → 停车 → 点"导出日志（直接发给我）"→ 把文件发我。**
截图顶多顺手截一张小程序电压、一张高德的本次里程，用来交叉核对时间点。

导出的 CSV 里每条都带 `epoch_ms`，`REC`/`SUM` 行还额外带 `HH:mm:ss`，所以
"你在 21:19 截的那张图"可以直接在日志里找到同一秒。

## 日志字段速查（我用来做标定和复盘的，你不用管）

| 字段 | 含义 | 拿来判断什么 |
|---|---|---|
| `v` | 控制器原始端电压（带载） | 和小程序比对是否同源 |
| `dv` | 真正上屏的电压 | 停车后应等于 `ocv`（静置口径） |
| `src` | 电压来源：0 无 / 1 BLE / 2 手动 / 3 推算 | 有没有在吃兜底值 |
| `ocv` | 45 秒静置滤波后的开路电压 | 和小程序对齐的关键量 |
| `sag` | 按"速度+油门"估的压降 | 反算 1.2V/油门、0.06V/(km/h) 这两个系数 |
| `thr` | 转把电压 | 判"是不是在出力"，上坡是否被误扣电 |
| `spd` | 上屏的 GPS 时速 | 和高德比 |
| `km` / `odo` | 本次里程 / 整车累计 | 和高德"本次里程"、车上累计比 |
| `soc` / `sv` | 显示电量 / 纯电压口径电量 | 两者差值就是"电压信不信"的指标 |
| `aa` / `ak` | 电量锚点（%）和它的里程坐标 | 判断电量是"按里程走"还是"被电压拽" |
| `pk` / `usr` | 学到的 %/km / 设置里的满电续航 | 学偏了没有（80km 对应 ≈1.25%/km） |
| `nud` / `rcv` | 纠偏已用 / 回升已用（预算各 12、10 点） | 一天下来被拽了多少 |
| `wh` | 每公里电耗（由能量守恒倒算） | 和 80km 基线是否自洽 |

没有 `c`（电流）、没有轮速 —— 67 字节帧里确实没有这两个字段（3820 帧逐字节穷举证实过），
所以功率、电机温度这类只能靠能量倒算，不是漏记。

## 我这轮还顺手改的

- 日志体积：`REC` 每 2 秒一条约 110 字节 → 每小时约 190KB，对总量几乎无影响（原始帧才是大头）。
- 导出按钮改名为**"导出日志（直接发给我）"**，位置不变（设置页）。
- `SUM` 在"清零/停车 60 秒/退服务"三个时机都会写，所以哪怕你跑完直接锁屏、被系统杀掉进程，
  这一趟的账也已经落盘了。
