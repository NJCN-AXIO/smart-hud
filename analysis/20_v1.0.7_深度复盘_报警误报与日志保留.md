# v1.0.7 深度复盘：5 个真问题（3 个是上一版埋下的）

这轮不新增功能，只做审查。逐条把"会让人当场炸毛"的写下来。

---

## 1. 🔴 严重：防盗报警会每进一次商场就响一次

**旧逻辑**：停稳 60 秒 + 蓝牙断开 + 离锚点 >25m + 持续 20s → 报警。

**问题**：这个功能拿**手机的 GPS** 当车的 GPS。而外卖骑手停车后 99% 会**把手机带走**。
人走进商场 300 米，手机就"离开锚点 300 米"、蓝牙也是断的 —— 20 秒后必然报警。
等于每送一单响一次，用户第一次遇到就会把这个功能永久关掉，甚至以为是 App 坏了。

**v1.0.7 改成三道出口**：
| 情形 | 判定 | 动作 |
|---|---|---|
| 蓝牙连上 | 车通电、人在车上 | 解除 |
| 手机以 **<12km/h** 离开锚点 | 人拿着手机走了 | 解除并记日志（不响） |
| 手机以 **≥12km/h** 离开锚点并持续 15 秒 | 车被**骑**走 | 报警 |

判定用的速度不是 GPS 速度字段（噪声大），而是 `位移 / 距上次定位的间隔`，更稳。

## 2. 🔴 严重：车真被骑走时，反而不报警

**旧逻辑**：`exitParked()` 里一句 `parkAnchor = null`。
车被骑走的那一刻，速度 >3.5km/h → 状态机从"停车"切到"骑行" → 锚点被抹掉 →
报警条件里的 `parkedMode && parkAnchor != null` 永远不成立。

也就是说：**最该报的场景（车被骑跑）恰好被这段代码删掉了**，
只剩"慢慢挪动且没被判定为骑行"的极小窗口。这是典型的"两个状态机耦合"错误。

**修法**：报警锚点与"停车/骑行"状态机**解耦**。
- 锚点由 `maybeArmAlarm()` 建立，只在"停稳 5 分钟 + 蓝牙断开 + 半小时内真连过控制器"时武装；
- 解除条件只有三个：蓝牙连上 / 手机步行离开 / 已报警；
- `exitParked()` 不再碰锚点。

另外加了 `lastConnOkTs` 闸门：手机整天没连过车却以车速度移动 → 那是人在坐车/坐公交，不武装。

## 3. 🟠 中：长按弹窗里的「上次骑行」会被 0.4km 的取餐停靠覆盖

`writeTripSummary()` 每次停车（含等红灯 60s）都会把 `lastTrip` 写一遍，
于是"上次骑行"经常变成 `0.4km · 2分钟 · 均速 12` —— 看着像坏了。

**修法**：只有 `本次里程 - 上次记录点 ≥ 3km` 才算新的一趟；否则只在日志里记一行，不动界面。
清零时把记录点归零。

---

## 4. 🟠 中：「本箱电已用 Wh」被长按清零清零了

`whThisCharge` 复用 `cycleSoc`，而 `resetTripInMemory()` 每次清零都会把 `cycleSoc`
改成"当前电量"（当初是为了防止电量跳回 100%）。副作用：
本箱电的账每清一次里程就归零，名不副实。

**修法**：新增独立账本 `chargeSoc / chargeKm`，**只由 `maybeAnchorFull()`（真正充满）建立**，
清零不动它。现在"本箱电已用 268Wh"是一箱电跨多次出车的真实累计。

## 5. 🟡 轻：9MB 的骑行日志会被"只留 12 个"挤掉

`KEEP_FILES = 12`，而每启动一次 App 就新开一个文件。
骑一趟产生 9MB 日志，后面开关机十几次，这趟日志就被当成"旧的"删了 ——
用户那趟 10:05 的骑行主体（2000 帧）就是这么丢的，事后无法复盘。

**修法**：
- 12 → **24** 个；
- **24 小时内的一律不删**（按时间保护今天的）；
- 顺手修了 `size += row.length()`（数的是字符，中文一行 3 字节 → 16MB 门槛实际能长到 40MB+），改按 UTF-8 字节计。
