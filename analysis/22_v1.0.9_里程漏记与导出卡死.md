# v1.0.9：里程会漏记 + 导出日志会把手机卡死

## 1. 🔴 里程漏记（这条直接影响"里程要精准"）

`tick` 里把 GPS 里程折算成"本次里程"的代码长这样：

```java
float moving = Float.isNaN(HudState.gpsKmh) ? 0f : HudState.gpsKmh;
if (gk > lastGpsKm && moving >= 3f) trip.addKm(gk - lastGpsKm);
```

问题在于 `HudState.gpsKm` **只会在 TrackDistance 过滤通过之后才增长**
（精度、抖动、跳点、速度一致性四道闸都过完了）。这里又加一道"显示速度 ≥3km/h"，
是纯粹的重复条件，而且是有害的：

- 城市/高楼区 `Location.getSpeed()` 的速度精度经常被判不合格（`speedAccuracy > 1.5` 且低速），
  这条数据会被丢掉；`SpeedStabilizer` 只保持 **4 秒**，之后就变 NaN；
- 于是那几十秒里：**gkm 在涨，里程一条都不记**。
  表现为"跑了一段，里程表没动"；里程偏少，电量推算（按里程走）也跟着偏乐观。

**修法**：只要"过滤后的里程涨了（≥1m）"就记，与显示速度彻底解耦。
停车时 `parkedMode` 走的是 `rebind`（step=0），所以不会凭空涨。

## 2. 🟠 导出日志可能把手机卡死 / 微信发不出去

旧版导出 = **把所有日志文件全并成一个 CSV**。现在保留 24 个文件、单文件上限 16MB，
最坏情况是一次复制几百兆，然后塞给微信分享 —— 点下去像没反应，甚至 OOM。

**修法**
- 只导 **最近 24 小时** 的文件（骑手要的就是今天这趟）；
- 总量上限 **40MB**，超了就跳过并如实说明；
- 24 小时内一个都没有，退回"最新的那个文件"；
- 顺手清掉 7 天前的 `export_*.csv`（以前只导出不清理，目录会一直涨）；
- Toast 改成"合并 N 个日志、M 行、多少 KB"，点了就知道到底导了什么。
