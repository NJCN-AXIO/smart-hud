# v1.0.4：按骑手的两个"基准"来对齐 —— 小程序看电压，高德看速度里程

日期：2026-11-18　版本：1.0.4 (versionCode 41)

骑手给了三个可对齐的基准：
1. **微信小程序（育宁科技）的电压** —— 同一个 67B 字段，看着"准"；
2. **高德导航的速度和里程** —— 骑行时一直开着；
3. **车仪表上的整车累计里程**（约 11220km，待确认真值）。

这轮的目标不是"再调参数"，而是**把口径往这三个基准上贴**。

## 一、电压：往"小程序同源"贴（5s/0.75 分位 → 3s/0.9 分位）

小程序的电压是**最新一帧**直接显示（不做滤波）。我们之前为了压抖动用 5 秒窗 0.75 分位，
副作用是"带载压降被算进去"——同刻小程序 68.6V、App 66.1V，骑手一看就觉得不准。

改：显示窗 `VoltFilter(3000ms, 48, 0.9)`。3 秒窗里取 0.9 分位，等价于
"取最近几帧里接近松油门的那一帧"，读数抬高约 0.5–2V，与小程序差值压到 1V 内，
同时仍然不会像原始瞬时值那样 ±5V 乱跳。

> 后台算法不受影响：停车校准仍用 45 秒/0.9 分位的 `restFilter`，
> 电量锚点、里程推算都没动。

## 二、速度/里程：把高德那套"一致性校验"搬过来

高德/Strava 都做一件事：**用 GPS 报的速度去校验位移**，而不是只用固定阈值。

`TrackDistance` 新增 `speedFactor=1.6, speedSlackKmh=6`：
位移/时间推出的速度 > `真实速度 × 1.6 + 6` 时，这一步当跳点丢弃（重新对表，不计里程）。

为什么必须有这一道：
- 原来的 `maxSpeedKmh=80` 只看绝对上限 —— 1 秒瞬移 15m（≡54km/h，外卖车根本跑不到）
  既没超 200m 也没超 80km/h，会被当成真实位移记进去；
- 城市峡谷/高架下这种 10–20m 的中等跳点很常见，一趟能虚增几百米。
- 有速度时用速度当尺子，比任何固定阈值都准；**停车漂移（速度 0.4km/h）走原来的抖动分支**，
  不会被这道校验误伤（为此专门补了一条单测锁住这个边界）。

## 三、整车累计里程：11220 基准 + App 累计

- `Prefs`：`odoBaseKm`（默认 **11220**，可改）、`odoAccumKm`（App 累计）。
- 每次"长按清零"：先把本次里程累加进 `odoAccumKm`，再归零（清零弹窗会写明
  "本次 X km 会累加进整车累计，清零后 ≈ Y km"）。
- 界面：`HudState.odoKm = 基准 + App 累计 + 本次`，显示在**长按状态行展开的诊断行**里
  （`整车=112xxkm`），不占主屏三个大数字的位置；设置页里有专门一节显示与编辑。
- 只是显示口径：不参与电压/电量/续航的任何计算。

## 四、参考高德：把导航通知那行"剩 X 公里 · X 分钟"借过来

高德没有给第三方 App 的公开"实时剩余里程"接口（要用它的导航 SDK + key，等于自己做导航）。
但骑手开导航时，**系统通知栏里本来就有那行字**。新增 `NavBridge`（`NotificationListenerService`）：

- 只读两个包：`com.autonavi.minimap`（高德）、`com.baidu.BaiduMap`（百度）；
- 取 `EXTRA_BIG_TEXT / EXTRA_TEXT`，只认含"剩余/公里/分钟/到达"的文案，
  前面加「高德 · 」原样显示（不猜格式，避免解析一改就失效）；
- 15 分钟没更新自动不显示；导航结束（"已结束/到达"）立即清掉；
- HUD 底部多一行绿色小字（13sp），没有就整行不出现；
- 设置页新增"导航信息（可选）"一节：显示是否已授权 + 一键跳到系统的「通知使用权」页。

**权限**：系统设置 → 通知与状态栏 → 通知使用权 → 勾选「Delivery HUD」。
不授权不影响任何其它功能（读通知失败也只是这行不显示）。
